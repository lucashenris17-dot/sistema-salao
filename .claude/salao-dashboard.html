Objetivo do Sistema

Sistema de gestão de salão de beleza para Inácia (profissional autônoma). Permite que clientes agendem horários online e acompanhem o atendimento em tempo real, enquanto a Inácia gerencia tudo pelo painel admin.

Dois Modos
Agendamento — cliente escolhe data/hora, Inácia aprova
Fila — cliente entra presencialmente
Acompanhamento
Cada atendimento tem token único
Cliente vê status em tempo real
⚙️

Stack Tecnológica

Framework: Next.js 16.3.4
UI: React 19.2.8
Linguagem: TypeScript (strict)
Estilo: Tailwind CSS
Banco: Supabase (PostgreSQL)
Auth: Supabase Auth
Realtime: Supabase Realtime

Arquitetura do Sistema

🔑 Conceito Crítico: Dois Campos de Status

status (operacional)
aguardando → em_andamento → pausado → finalizado/cancelado/no_show
status_confirmacao (aprovação)
pendente → confirmado/recusado
⚠️ São ortogonais: Um atendimento pode estar "aguardando" (operacional) e "confirmado" (aprovado) ao mesmo tempo.

📊 Modelo de Dados

atendimentos
id, cliente_id, procedimento_id, modo, status, status_confirmacao, horario_agendado, ordem_fila, token_acesso, duracao_trabalhada_seg, pausado_desde
clientes
id, nome, sobrenome, whatsapp (UNIQUE)
procedimentos
id, nome, duracao_estimada_min, ativo
bloqueios_agenda
id, inicio, fim, motivo

🔐 Segurança (RLS)

anon_atendimentos_select_proprio_token
Anon pode SELECT em atendimentos filtrando por token_acesso
anon_atendimentos_insert_pendente
Anon pode INSERT com status_confirmacao = 'pendente'
fn_buscar_atendimento_publico
RPC SECURITY DEFINER — controla o que anon vê

🔄 Fluxos Principais

Cliente (Agendamento)
  1. Acessa /agendar
  2. Preenche 4 etapas
  3. Sistema cria: status='aguardando', status_confirmacao='pendente'
  4. Gera token único
  5. Redireciona para /acompanhar/[token]
  6. Admin aprova → status_confirmacao='confirmado'
  7. Admin inicia → status='em_andamento'
  8. Admin finaliza → status='finalizado'
Admin (Gestão)
  1. Vê solicitações em /admin/solicitacoes
  2. Aprova: só muda status_confirmacao
  3. Recusa: status='cancelado' + status_confirmacao='recusado'
  4. Gerencia em /admin/atendimentos
  5. Iniciar/Pausar/Retomar/Finalizar
  6. Cancelar/No-show

🔧 Integrações Chave

🔴 Supabase Realtime
Página do cliente atualiza automaticamente via postgres_changes na tabela atendimentos
supabase.channel('atendimento-atualizado')
  .on('postgres_changes', {...})
  .subscribe()
📊 Algoritmo de Previsão
calcularPrevisao() em src/lib/previsao.ts — calcula inicio_previsto, fim_previsto e minutos_restantes para cada atendimento na fila
🔐 Token de Acompanhamento
Token opaco gerado por gerarTokenAcompanhamento() — URL pública /acompanhar/[token] sem login
